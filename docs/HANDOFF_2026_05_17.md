### What we might have missed

Things I'd flag for next-session attention:

1. **Spec status sweep never happened.** All 47 specs are `draft`. The spec 02 R7 lifecycle says "shipped" or "reviewed" should reflect implementation reality. If we're being honest about the state, half the specs should be at least `reviewed`. Not high-priority but the lifecycle discipline is broken.

2. **Real ErosionKernel doesn't run in walking_demo yet.** The demo script proves the chain works; the live renderer still reads `kernels/noise_stack.json`. So while we shipped the kernel system end-to-end Python-side, the user can't actually SEE eroded terrain in the demo. The bake-script comparison PNG at `engine/worlds/walking_demo/captures/erosion_comparison.png` is the only visual proof.

3. **Phase 6 visual A/B never done.** Forest slots are now active in the render path but the user hasn't relaunched the demo + confirmed the alpine↔forest auto-rule crossover works. Possible visible bugs: (a) crossover band too narrow → hard seam at 10m elev; (b) too wide → both biomes blended everywhere; (c) per-tier sibling_blend_freq might wash out the biome boundary. **Need user launch + screenshot.**

4. **`_pending_kernel` pattern not established** (only `_pending_slots`). When the user wants to test catalog-driven kernel before the loader switch ships, they could put the new kernel chain in `_pending_kernel` and have the runtime still read the old kernels/noise_stack.json. This is a tiny convention worth establishing now if we're going to do the loader switch in 1-2 sessions.

5. **Per-biome kernel chains untested end-to-end.** Walking_demo's alpine + forest both use the same noise_stack. When someone authors a catalog where biomes have genuinely different chains (e.g. alpine + erosion vs forest + no-erosion), the Composer's multi-biome height blending kicks in. The Composer's `sample_height` currently averages all biomes' chain outputs uniformly — NOT weighted by per-(x,z) biome_weights. This works for walking_demo (identical chains) but will produce a soft blur if chains diverge. **Real fix**: weight `sample_height` by `biome_weights(x, z, h_estimate, slope_estimate)`. Iterative since h depends on weights depending on h. Not blocking until a real catalog with divergent chains exists.

6. **GPU mutex with TRELLIS** (audit S5) — pre-emptive scheduled. Not blocking until Phase 6 (now closing) overlaps with Phase 7+ TRELLIS authoring.
