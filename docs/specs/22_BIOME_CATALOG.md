# Spec: Biome Catalog

> Status: shipped (2026-05-18; promoted per spec-to-impl audit — catalog + auto_biome_rules + per-biome surface_slots + softmax wired Phase 6)
> Tier: 1 (core)
> Depends on: 19_KERNEL_SYSTEM, 20_TERRAIN_BACKEND, 14_WORLD_CONTRACT
> Consumed by: terrain backend, materials, decoration, audio hooks, nav, weather/climate, world contract validator

## Purpose

The per-world manifest of "what biomes exist + their properties."
Each world bundle (`worlds/<name>/biome_catalog.json`) is the
source of truth for biome assignment, per-biome kernel config,
material kit reference, decoration palette reference, audio tags,
climate defaults, and nav rules.

Cross-referenced by basically every other system. World contract
validates the catalog at preflight time.

W4.1 had this and it worked. W5 keeps the structure, formalizes
the schema from v1 (W4's grew incrementally), and adopts the
hybrid biome-assignment model (auto-biome + splat overrides) per
inventory decision.

## Non-goals

- Authoring UI for catalogs (JSON edited by hand or generated by
  pipeline)
- Per-fragment biome decisions outside the catalog (the catalog +
  kernel produce biome weights; shaders + decoration consume them
  without making their own decisions)
- Multi-world catalogs (one catalog per world bundle)

## Catalog shape (skeleton)

```json
{
  "schema_version": 1,
  "world_name": "two_biome_demo",
  "biome_scale_m": 1024.0,
  "elevation_range_m": [25.0, 1400.0],
  "biomes": [
    {
      "name": "alpine",
      "kernel": {
        "type": "noise_stack",
        "params": { /* per-kernel config */ }
      },
      "material_kit": "materials/biome_alpine/",
      "decoration_palette": "biome_decoration/alpine.yaml",
      "audio_tag": "ambient/alpine_high_altitude",
      "climate_base": {
        "reference_elevation_m": 1000.0,
        "moisture": 0.3,
        "temperature_c": 5.0,
        "wind_exposure": 0.8
      },
      "surface_slots": {
        "ground": { "weight": 1.0 },
        "mid":    { "weight": 1.0 },
        "rock":   { "weight": 1.0 }
      },
      "auto_biome_rules": {
        "elevation_m": [800, 1400],
        "slope_deg":   [0, 60]
      },
      // NOTE: auto_biome_rules is intentionally geometry-only
      // (elevation + slope). Per-XZ climate (temperature / moisture /
      // wind) is a CONSEQUENCE of biome assignment + position via
      // climate_rules below, not an INPUT to it. If you want
      // climate-driven biome selection (e.g. "tropical at any
      // elevation if temp > 25C"), add a climate field to the rule
      // set here in a future schema bump — v1 stays geometry-only
      // to keep the assignment deterministic + cheap.
      "nav_default": "walkable"
    },
    {
      "name": "wetland",
      /* ... */
    }
  ],
  "splat_overrides": [
    {
      "name": "altar_grove",
      "bounds": {"x0": -300, "z0": -300, "x1": -200, "z1": -200},
      "biome": "alpine"
    }
  ]
  // SA-M3.5: splat_overrides INSIDE biome_catalog.json are
  // CATALOG-SHIPPED defaults (baked into the world). For per-author
  // overlay edits or per-save consumer overrides, use
  // biome_overrides.json per spec 39 (loaded at world load, layered
  // on top of the catalog).
}
```

## Biome assignment model

Two-layer hybrid (per inventory decision):

1. **Auto-biome from rules** (default, runs world-wide): every world
   XZ has biome weights computed from its terrain features (elevation,
   slope) + climate against per-biome `auto_biome_rules`. Softmax
   over matching biomes produces weight distribution at that XZ.
2. **Splat overrides** (optional, local): named axis-aligned rectangles
   that hard-assign a biome regardless of auto-biome rules. Used for
   hand-authored set-pieces. Splat-override wins inside its bounds;
   auto-biome resumes outside.

The terrain backend's biome-mask output is the resolved blend of both
layers at each XZ.

```python

    def biome_names(self) -> list[str]: ...

        """Returns biome→weight at (x, z). Honors splat overrides."""
```

GDScript: mirror API for runtime consumption.

## Producer / consumer contract

- **Produces**: per-(x, z) biome weights; per-biome metadata
  (material kit, decoration palette, audio tag, climate defaults,
  nav rules)
- **Consumes**: kernel composer for auto-biome evaluation; world
  contract preflight for schema validation

## Climate fields + regional gating

Every biome has a `climate_base` block defining the biome's
**reference climate at its reference elevation**:

```json
"climate_base": {
  "reference_elevation_m": 1000.0,
  "moisture": 0.3,
  "temperature_c": 5.0,
  "wind_exposure": 0.8
}
```

Plus the world catalog declares **regional gating rules** that adjust
the base climate per (x, z) location:

```json
"climate_rules": {
  "temperature_lapse_c_per_km": -6.5,
  "moisture_from_distance_to_water": {
    "max_distance_m": 5000.0,
    "moisture_at_water": 1.0,
    "moisture_at_max_distance": 0.1
  },
  "wind_from_exposure": {
    "ridge_multiplier": 1.5,
    "valley_multiplier": 0.5
  }
}
```

The kernel composer (spec 19) reads `climate_base` + `climate_rules`
and computes **per-XZ climate** as (note SA-M3.6: distance-to-water
rule degrades to base moisture if spec 35 water hasn't shipped or
the world has no water bodies — this degraded state persists from
Phase 4 through Phase 9, since water ships in Phase 10; weather in
Phase 11 will read flat-per-biome moisture until water lands):

- `temperature_c(x, z) = climate_base.temperature_c + (elevation(x,z) - reference_elevation_m) * (lapse / 1000)`
- `moisture(x, z) = base_moisture interpolated by distance_to_nearest_water`
- `wind_exposure(x, z) = base_exposure * ridge/valley multiplier based on local slope/aspect`

This delivers the "alpine peak is colder than alpine base" effect that
audit C5 flagged was promised by inventory but missing in spec —
within-biome regional variation, not per-biome flat scalars.

Forward-compat: adding new climate fields or rules requires bumping
`schema_version` + a migration script per spec 17.

## Surface slot rules per biome

Each biome declares which surface slots it uses (`ground`, `mid`,
`rock`) with optional weight modifiers. Surface slot selector spec
(separate, under materials) consumes this.

## Quality bar

- Catalog parse + validate < 100ms for typical 4-biome world
- Splat override evaluation < 10µs per XZ query
- `sample_weights` < 50µs per call (cached internally)
- World contract catches: unknown biome name, missing material kit,
  duplicate biome names, splat-override referencing unknown biome,
  out-of-range climate values, conflicting auto_biome_rules
- 100% test coverage (pytest)

## Discoverability

- **Entry point**: `BiomeCatalog.load(path)` in Python; mirror in
  GDScript
- **Schema**: JSON Schema at
  `engine/resources/schemas/biome_catalog.schema.json`
- **Validator / preflight**: `python -m world5.world_contract --world X`
  validates the catalog
- **Example**: `demo/worlds/two_biome_demo/biome_catalog.json` is the
  reference; minimal one-biome example at
  `engine/examples/example_world/biome_catalog.json`
- **Deterministic outputs**: yes — same catalog + same kernel + same
  (x, z) → same weights

## Open questions

- **Splat override format**: axis-aligned rect is the simplest. W4
  used the same shape. Polygons + rotated rects would be more
  expressive but cost validator complexity. Defer; rect is enough
  for v1.
- **Catalog-level climate kernel**: RESOLVED (audit C5): per-XZ
  climate is computed by `climate_rules` (temperature lapse, moisture
  vs water distance, wind from local exposure) applied to per-biome
  `climate_base`. Replaces flat-per-biome scalars. Distance-to-water
  query consumed from spec 35 water bodies registry; if no water in
  the world, moisture rule degrades to base only.
- **Per-biome erosion config**: erosion params per-biome (some
  biomes are heavily eroded, others sharper)? Probably yes; defer
  schema until erosion is being tuned.
- **Biome inheritance**: can biome B "inherit from" biome A and
  override only a few fields? Convenience feature. Defer.
