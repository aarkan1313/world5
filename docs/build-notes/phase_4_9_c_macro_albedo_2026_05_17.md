## How it works end-to-end

1. **Author**: `python -m world5.textures.tx_macro_terrain --purpose-candidates --promote-purpose`
   - Reads `engine/worlds/walking_demo/biome_catalog.json`
   - For each biome, derives a macro variant from `<material_kit>/ground/albedo.png`
   - Builds a purpose-preset variant (alpine = snow + stone + ice + tint) at 1024²
   - Promotes purpose → `<material_kit>/ground/macro_albedo.png`
   - Drops comparison sheets at `<world>/captures/` (gitignored debug)
2. **Manifest**: world-root `macro_albedo.json` declares the world AABB + texture `res://` path
3. **Load**: `TerrainWorld._load_world_bundle` calls `_macro.load_from_path(macro_cfg)` →
   `MaterialPipeline.bind_macro_albedo` on every ring's shader material
4. **Render**: shader samples macro at world XZ for the Layer 3 blend, breaking
   per-page tile repeat at distance

## W5 vs W4 catalog mismatch (resolved this phase)

W4 catalogs used `kit_dir` (project-relative under GODOT_ROOT).
W5 catalogs (spec 22) use `material_kit` (world-bundle-relative).
The ported `tx_macro_terrain.py` only read `kit_dir`, so it would
have silently skipped the alpine biome on W5 layouts.

Fix in `_catalog_ground_layers`: try `material_kit` first (resolve
relative to catalog's parent dir = world bundle); fall back to
`kit_dir` (resolve relative to GODOT_ROOT) for any remaining W4-
shaped catalogs. Both code paths stay correct.

## What's load-bearing post-4.9.c

- The world-root `macro_albedo.json` shape is now the binding contract.
  Any future per-biome macro authoring (Phase 6 forest, etc.) needs
  one manifest per biome OR a single world-level manifest with a
  composite texture. Currently single-biome alpine → single manifest.
- The `_resolve_res_path` heuristic in `materials_manifests.py` is
  best-effort (no project.godot reader). If future res:// paths get
  more creative, the check returns `None` for unknown schemes rather
  than false-positiving.
- `captures/` dirs are derived artifacts; never commit. The .gitignore
  rule is broad (`engine/worlds/**/captures/`); applies to all worlds.

## Tileability caveat (Phase 5.4.b)

The 2×2 tiled comparison sheet shows the purpose macro has a visible
low-frequency pebble pattern that repeats. At world scale this means
a visible repeat at ~2 km, which is the visibility horizon. Not
critical for Phase 4 (still better than the olive fallback band)
but **flag for Phase 5.4.b**: either re-tune the purpose preset to
break the low-frequency pattern, or switch the alpine macro to the
"derived" variant (smoother tile, less character).
