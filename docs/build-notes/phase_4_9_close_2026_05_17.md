## Why this phase existed

Walking demo Phase 5.4 alpine render exposed three critical bugs
that violated specs 21+23+24. A 4-subagent re-audit found these +
9 significant + 9 minor gaps across phases 0-5. Phase 0+2 clean;
phases 4 / 4.5 / 4.6 / 5.4 / 5.5 all claimed ✅ done while shipping
unfinished core systems. Build notes were honest about deferred
work; ROADMAP+STATE glossed over the cuts. User direction: "we
will just need to fix everything we should have at this point,
reaudit the whole project as needed."

Phase 4.9 was opened to close the critical gaps before Phase 5.6
calibration or Phase 6 forest could start meaningfully.

## Lessons captured

1. **Shader-state assertions ≠ visual correctness.** The Phase 5.5
   integration tests asserted `has_siblings=true` + `sibling_count=4`
   + bound array — all true — and the walking demo still rendered
   wrong because (a) only the first slot bound, (b) rings culled by
   AABB, (c) outer rings stretched their single page. New regression
   guards added at the mesh + shader-output level to catch the bug
   class without needing SubViewport pixel capture.

2. **The build note → ROADMAP → STATE chain must close at every
   phase boundary**, or the docs drift again. Phase 4.9 close
   updates ROADMAP + STATE to reflect what build notes say. The
   `⚠️ shipped with gaps` marker stays on Phase 4 / 4.5 / 4.6 / 5.4
   / 5.5 until their specific deferrals are closed by the linked
   sub-phase.

3. **Each critical gap was a real architectural cut, not a typo.**
   Phase 4.9.a touched 3 files (helper + shader + composer) +
   created 1 new class. Phase 4.9.b touched 5 files (catalog + 2
   shaders + binder + composer) + created 2 new classes. The cost
   of skipping these in original Phase 4 was real — they HAD to be
   built eventually.
