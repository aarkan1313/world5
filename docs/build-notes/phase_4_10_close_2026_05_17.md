## What shipped

Three independent fixes for three distinct user-visible artifacts,
each citing the W4 pitfall that documented the failure mode.

### 4.10.b — Incremental RingHeightArray rebase (W4 PITFALLS #14)

**Bug**: "i can also clearly see the rings as i move" — page-bound
heightmap visibly chases the camera after every ring snap.

**Root cause**: `TerrainWorld._update_ring_height_array` lines
500-505 dropped the entire `RingHeightArray` on any ring snap +
re-streamed every page from scratch. Pages still inside the new
window were re-fetched anyway, causing visible placeholder ground
during the gap.

**Fix**: new `RingHeightArray.rebase(new_min_xz)` re-keys existing
pages to new local coords. In-window pages keep their image content;
out-of-window pages evict normally. Caller swap: instead of
`rha = RingHeightArray.new()`, call `rha.rebase(aligned_min)`.

**Files**: `engine/scripts/terrain/streaming/RingHeightArray.gd`
(+rebase method), `engine/scripts/terrain/TerrainWorld.gd`
(_update_ring_height_array swap). +3 TDD tests (RED → GREEN).

### 4.10.c — Killed redundant brightness modulator (W4 PITFALLS #31 class)

**Bug**: visible ~20m-scale blocky brightness patches across snow
surface ("tile to tile transitions" in user feedback).

**Root cause**: fragment shader line 305 was
`ALBEDO = base * (0.85 + 0.30 * nv)` where `nv = w5_world_noise(world_xz, 0.05)`
= 20m-wavelength noise. ±15% brightness modulation at 20m grid on
near-uniform alpine snow read as authored square cells, matching W4
PITFALLS #31's "world-stable square material regions can still look
like bugs" warning.

**Fix**: removed the noise modulator entirely. Macro albedo +
sibling textures provide all needed variation; this Phase 4 hack
was redundant once Layer 1 + Layer 3 shipped. If a future demo
needs very-large-scale brightness variation, author it into
`macro_albedo.png` content, not into a shader noise call.

**Files**: `engine/shaders/terrain_clipmap.gdshader` (removed `nv`
calculation + `ALBEDO = base * (0.85 + 0.30 * nv)` → `ALBEDO = base`).

**Note on plan-doc rename**: the 4.10 plan originally framed this
sub-task as "world-stable slope for slot selection (PITFALLS #30/#32)".
On diagnosis, the user's tile-pattern artifact turned out to be
PITFALLS #31's brightness-modulator class, NOT #30's slope-source
class. The slope sample is already at a fixed 1m world distance
across all rings (cell_m = page_extent_m / (grid_n - 1) ≈ 1m
uniformly), so #30 doesn't currently apply. Plan's #30/#32 fix can
land later if ring-bound slot disagreement actually surfaces in
multi-biome scenes.

### 4.10.a — Per-vertex morph factor (W4 PITFALLS #11)

**Bug**: visible elevation cliff at ring boundary in walking demo.

**Root cause**: `morph_factor` was a single per-ring uniform driven
by camera-to-ring-CENTER chebyshev distance via
`ClipmapDispatch.compute_morph_factor`. All vertices of a ring got
the same factor. When camera was anywhere near a ring's center,
morph_factor stayed at 0 → vertices at the ring's outer EDGE
sampled own-ring height (not parent-morphed) → cliff visible
wherever inner ring's outer edge met outer ring's inner edge.

Per W4 PITFALLS #11: "Each non-outermost ring's vertex shader
samples both this ring's heightmap AND the next coarser ring's,
blends them by a [0..1] factor that's 0 in the ring interior and
ramps to 1 inside a thin band near the ring's outer edge."

**Fix**: removed single `morph_factor` uniform. Added three new
per-ring uniforms: `ring_center_xz: vec2`,
`ring_half_extent_m: float`, `morph_band_frac: float`. Vertex
shader computes per-vertex morph from this vertex's chebyshev
distance to ring center. Outermost ring binds
`ring_half_extent_m = 0.0` → morph stays at 0 (no parent).

**Files**:
- `engine/shaders/terrain_clipmap.gdshader` (morph_factor uniform
  replaced; vertex shader computes per-vertex `m`)
- `engine/scripts/terrain/material/MaterialPipeline.gd` (new
  `set_ring_morph(mat, center_xz, half_extent_m, band_frac)`;
  legacy `set_morph_factor` retained as no-op for back-compat)
- `engine/scripts/terrain/TerrainWorld.gd` (calls `set_ring_morph`
  per ring; outermost binds half_extent=0 to disable morph)

## What's load-bearing post-4.10

- **The `morph_factor` uniform no longer exists in the shader.**
  Any GDScript that calls `mat.set_shader_parameter("morph_factor", ...)`
  is a no-op. Use `MaterialPipeline.set_ring_morph(...)` instead.
  `set_morph_factor` left as a back-compat no-op (logs nothing —
  truly silent). If a test asserted morph_factor was set, it will
  pass against the still-existing setter but the shader ignores it.
- **`RingHeightArray.rebase` is the canonical snap path.** Code
  that constructs `RingHeightArray.new()` mid-life will silently
  re-do the bug. Only construct on ring creation.
- **Outermost ring must bind `ring_half_extent_m = 0.0`** to disable
  morph; non-zero would morph toward nothing (h_parent equals h_self
  at the boundary by construction since parent_world_xz snap is
  on-grid for the outer ring too — harmless but wasteful).
